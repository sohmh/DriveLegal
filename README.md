# DriveLegal

DriveLegal is a local-first FastAPI and HTML/Streamlit application for authenticated Indian traffic-law Q&A, GPS-aware retrieval, challan estimation, and driver dashboard history.

## 1. Project Title and One-Line Description

DriveLegal is a location-aware road-safety assistant for Indian drivers that combines a FastAPI backend, local Qdrant retrieval, Ollama/Mistral generation, SQLite persistence, and an HTML dashboard.

## 2. Overview

DriveLegal answers natural-language traffic-law questions and returns indicative, source-backed guidance for a selected or GPS-resolved Indian jurisdiction. The main user experience is `frontend/ui.html`, a static HTML/CSS/JavaScript dashboard embedded by `frontend/app.py` in Streamlit and also served directly by FastAPI at `/ui`.

The backend is a single FastAPI service (`app/main.py`) with routers for email OTP authentication, chat, GPS location updates, and profile/dashboard data. It stores users, violations, and chat messages in the root SQLite database configured by `app/database.py` as `sqlite:///./drivelegal.db`.

**Jurisdiction scope model**: DriveLegal uses GPS or manual city/state/country values plus Qdrant `region` payloads to prioritize local Indian traffic-law chunks before broader state and national material. This is implemented as an ordered scope cascade rather than separate hierarchy columns in the processed chunks.

**International and regional scope layer**: The modified RAG/fine pipeline also includes `rag/jurisdiction.py`, which extends the location cascade beyond India. It can try city, state/province, country, regional bloc (`EU`, `ASEAN`, `GCC`), the `Vienna Convention on Road Traffic`, and finally an unfiltered fallback. The bundled corpus is still primarily India-focused, so international coverage depends on matching source chunks and `data/fines.json` entries.

The AI path is local-first. `rag/retriever.py` loads a local embedded Qdrant collection from `data/qdrant_db`, embeds user queries with `sentence-transformers` model `all-MiniLM-L6-v2`, and returns location-filtered law chunks. `rag/chain.py` sends retrieved context to local Ollama model `mistral` through LangChain's `ChatOllama`; if the model call fails, it falls back to direct Qdrant retrieval and then `data/cache.json`.

Structured fine amounts are not generated by the LLM. `rag/challan.py` detects violation and vehicle keywords, then looks up exact strings in `data/fines.json` using city -> state/province -> country/national -> regional bloc -> international convention priority. `lookup_fine_details()` also returns currency metadata and a static USD-equivalent hint for the API response.

## 3. System Architecture

This is a local client-server application with an offline-capable RAG/indexing pipeline. It is not implemented as microservices: one FastAPI process hosts all API routes, startup initialization, database table creation, and Qdrant index loading. A separate Streamlit process can host the UI wrapper, but the browser JavaScript calls the FastAPI backend directly.

## 4. Use-Case Workflow

### Email OTP login and dashboard bootstrap

1. The browser loads `frontend/ui.html` through Streamlit (`streamlit run frontend/app.py`) or FastAPI (`GET /ui`).
2. The user enters an email address.
3. The UI posts `{ "email": "..." }` to `POST /api/auth/send-otp`.
4. `app/auth.py` generates a six-digit OTP, stores it in the module-level `otp_store`, and sends the code through `smtplib.SMTP_SSL`.
5. The user enters the OTP.
6. The UI posts `{ "email": "...", "code": "..." }` to `POST /api/auth/verify-otp`.
7. The backend validates the in-memory OTP, creates a `users` row if needed, signs a JWT with `JWT_SECRET`, and returns `token`, `is_verified`, and `user_id`.
8. The UI stores the token in `localStorage` under `drivelegal_jwt`, then calls `/api/profile/dashboard-data/{user_id}` and `/api/profile/chat-history/{user_id}`.

### Primary chat workflow
![Use-Case Workflow](https://github.com/sohmh/DriveLegal/blob/main/drivelegal-primarychatworkflow.png)


### GPS workflow

1. The user enables GPS in the right-side dashboard panel.
2. Browser `navigator.geolocation.watchPosition` collects coordinates.
3. The UI posts `{ lat, lon, accuracy, client_timestamp }` to `POST /location/update` immediately and every 10 seconds while a fix exists.
4. `app/routes/location.py` resolves coordinates with `geocoding/offline_geocoder.py` and maps them to city, state, and country fields.
5. The latest resolved `LocationResult` stays only in process memory.
6. `/chat` uses that GPS location and its corresponding jurisdiction level instead of the manual dropdown while the fix is fresh, enabling precise jurisdiction-aware content retrieval.

### International/regional fine fallback workflow

1. `/chat` passes the effective `city`, `state`, and `country` into `lookup_fine()` and `lookup_fine_details()`.
2. `rag/jurisdiction.py` builds candidate fine scopes from the location: city, state/province, country or `national`, regional bloc, and `Vienna Convention on Road Traffic`.
3. `rag/challan.py` detects the violation and vehicle type, then checks those scopes in order against `data/fines.json`.
4. The response can include the original display amount, currency code/symbol, and a static USD-equivalent hint. These exchange hints are convenience metadata, not live FX rates.

### Driver profile verification workflow

1. After login, if `profile.is_verified` is false, the UI shows a one-time license-linking form.
2. The UI posts email, DL number, and DOB to `POST /api/profile/verify-dl`.
3. `app/routes/profile.py` finds the existing user by email.
4. Current code checks whether the DL number contains `ANURAG` or `TEAMKALKI`; if so, it uses the matching sample profile. Otherwise it uses a default profile and violation.
5. The route marks the user verified, saves DL/profile fields, clears existing violations for the user, inserts selected violations, and returns profile details.
6. The UI reloads dashboard and chat history.

### Corpus ingestion and indexing workflow

1. Add source files to `data/raw` using supported extensions: `.txt`, `.md`, `.pdf`, `.csv`.
2. Run `python scripts/preprocess.py`.
3. The script extracts text, strips non-ASCII characters, chunks text with `RecursiveCharacterTextSplitter`, adds inferred `source`, `filetype`, `chunk_index`, `region`, `category`, and `law_section` metadata, and writes `data/processed/chunks.json`.
4. Run `python scripts/migrate_to_qdrant.py`.
5. The script loads `data/processed/chunks.json`, generates normalized 384-dimensional embeddings with `all-MiniLM-L6-v2`, recreates Qdrant collection `drivelegal_chunks`, stores the metadata payloads used by exact `region` filters, and writes local embedded Qdrant storage under `data/qdrant_db`.

## 6. How the Tech Stack Works Together

`app/main.py` is the backend entrypoint. On startup it loads `.env`, creates SQLite tables from SQLAlchemy models, and calls `rag.retriever.load_index()`. The app will fail startup if Qdrant collection `drivelegal_chunks` is not available at `data/qdrant_db`; the error message tells the operator to run `python scripts/migrate_to_qdrant.py`.

The browser UI uses a hardcoded backend origin, `http://127.0.0.1:8000`, in `frontend/ui.html`. `frontend/app.py` does not read `BACKEND_URL`; it only embeds the static HTML in Streamlit. If the API runs somewhere else, `frontend/ui.html` must be changed or made configurable.

Authentication is split between browser storage and backend JWT validation. The UI stores the token in `localStorage` and sends it as `Authorization: Bearer <token>` to `/chat`. FastAPI's `HTTPBearer` dependency makes `/chat` require a bearer token before route logic runs. Dashboard/profile endpoints accept `user_id` path parameters and do not currently require the JWT.

**Jurisdiction and treaty scope resolution**: The GPS and location workflow resolves browser coordinates to city, state, and country through `geocoding/offline_geocoder.py`; manual dropdown values follow the same request shape. `rag/jurisdiction.py` then builds the ordered scope list used by retrieval and fine lookup: city -> state/province -> country/National -> regional bloc (`EU`, `ASEAN`, `GCC`) -> `Vienna Convention on Road Traffic` -> unfiltered fallback.

The RAG runtime depends on three local services/artifacts being ready: the FastAPI process, the embedded Qdrant collection under `data/qdrant_db` with `region`, `category`, and `law_section` payloads, and an Ollama daemon with the `mistral` model available. Qdrant and the sentence-transformer model are loaded in-process; Ollama is contacted through LangChain's `ChatOllama`.

The ingestion pipeline is offline after dependencies/models are installed. `scripts/preprocess.py` creates `data/processed/chunks.json` with one `region` metadata value per chunk plus `category` and `law_section`; `scripts/migrate_to_qdrant.py` turns that JSON into the Qdrant collection used for exact region filters. `rag/retriever.py` then reads only the Qdrant store at runtime, not the raw PDFs/CSVs.

Structured fine lookup runs alongside RAG. `/chat` always calls `lookup_fine()` after `get_answer()`, then calls `lookup_fine_details()` when a fine exists. This can attach `fine_amount`, `currency_code`, `currency_symbol`, `usd_equivalent`, and `usd_equivalent_display` from `data/fines.json` even when the generated answer comes from the LLM or fallback path.

SQLite is used directly in the FastAPI process through SQLAlchemy sessions. The configured database file is `./drivelegal.db` relative to the process working directory. A second `app/drivelegal.db` file exists in the repository, but the current `DATABASE_URL` does not point to it.

### Jurisdiction and Treaty Scope Layer

DriveLegal is still India-first, but the modified project now has a shared scope helper for both RAG retrieval and deterministic challan lookup.

**Scope order used by the code:**
```text
City
  -> State / province
  -> Country or National alias
  -> Regional bloc: EU, ASEAN, GCC
  -> Vienna Convention on Road Traffic
  -> Unfiltered fallback
```

**How it works:**

1. **Metadata Tagging**: `scripts/preprocess.py` writes one `region` metadata value per chunk, plus `source`, `filetype`, `chunk_index`, `category`, and `law_section`. It does not currently write separate `national`, `state`, `city`, or `local` fields.
2. **Scope Construction**: `rag/jurisdiction.py` normalizes India aliases (`India`, `Indian`, `Bharat`) to include the `national`/`National` fallback, detects EU/ASEAN/GCC countries, and appends `Vienna Convention on Road Traffic`.
3. **Cascading Retrieval**: `rag/retriever.py` queries Qdrant once per scope with an exact `region` filter, deduplicates document IDs, and stops when enough results are collected. The final empty scope performs an unfiltered vector search.
4. **GPS-to-Jurisdiction Mapping**: `geocoding/offline_geocoder.py` resolves browser coordinates to `city`, `state`, and `country`, then `/chat` passes those values into both RAG and challan lookup. Fresh GPS fixes override the manual dropdown.
5. **Fine Lookup Integration**: `rag/challan.py` uses the same scope idea for `data/fines.json`, checking city, state/province, country/national, regional bloc, and the Vienna Convention fallback in order. `lookup_fine_details()` enriches matches with currency and static USD-equivalent metadata.

**Benefits:**
- Keeps location-specific Indian legal guidance precise while preserving national fallback behavior.
- Gives the code a clean extension point for non-Indian countries and regional road-traffic rules.

## 9. Setup & Installation

Recommended manual setup from a clean clone:

```powershell
git clone <repo-url>
cd DriveLegal

python -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m pip install pdfplumber

copy .env.example .env
```

Edit `.env` and set at least:

```dotenv
SMTP_SERVER=smtp.gmail.com
SMTP_PORT=465
SENDER_EMAIL=your_email@gmail.com
SENDER_PASSWORD=your_app_password
JWT_SECRET=replace_with_a_long_random_secret
GPS_MAX_AGE_SECONDS=60
```

If live Surepass integration is later implemented, also set:

```dotenv
SUREPASS_API_BASE_URL=https://api.surepass.io/api/v1
SUREPASS_AUTH_TOKEN=your_surepass_token
```

Install and prepare Ollama:

```powershell
ollama pull mistral
ollama serve
```

If `ollama serve` reports that Ollama is already running, keep the running daemon.

Build or refresh the local retrieval index:

```powershell
python scripts\preprocess.py
python scripts\migrate_to_qdrant.py
```

Start the backend:

```powershell
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

Start the Streamlit UI in a second terminal:

```powershell
.\venv\Scripts\Activate.ps1
streamlit run frontend\app.py
```

Open:

| Surface | URL |
| --- | --- |
| Streamlit UI | `http://localhost:8501` |
| Direct FastAPI-served UI | `http://localhost:8000/ui` |
| API docs | `http://localhost:8000/docs` |
| Health check | `http://localhost:8000/health` |

Windows helper scripts:

```powershell
scripts\setup_gps.bat
start.bat
```

Do not rely on `setup.bat` for full setup until its missing `scripts\embed.py` reference is corrected to `scripts\migrate_to_qdrant.py`.

Run tests after installing dependencies:

```powershell
python -m pytest tests -q
```

## 11. Known Limitations / TODOs

- TODO: confirm live Surepass/Parivahan integration. `app/routes/profile.py` reads `SUREPASS_API_BASE_URL` and `SUREPASS_AUTH_TOKEN`, but current code never imports `requests`/`httpx` or performs a live Surepass call.
- TODO: confirm license. The previous README stated MIT, but no standalone `LICENSE` file exists.
- TODO: enhance jurisdiction scopes with local/micro-jurisdiction levels (e.g., police station jurisdictions, municipal corporation zones).
- TODO: optimize scope filtering performance with Qdrant payload indexes and more explicit city/state/country metadata.
- `setup.bat` references `python scripts\embed.py`, but no `scripts/embed.py` exists. The actual Qdrant build script is `scripts/migrate_to_qdrant.py`.
- `scripts/preprocess.py` imports `pdfplumber`, but `requirements.txt` does not list it.
- `/chat` requires a bearer token through `HTTPBearer`. Current `tests/test_api.py` posts to `/chat` without an `Authorization` header, so the tests likely need updates.
- `rag/retriever.retrieve()` returns `(documents, top_score)`, but parts of `tests/test_rag.py` mock it as a bare list, so those tests appear stale.
- The checked-in `venv` is not portable and failed to run in this environment because its Python launcher points to `C:\Users\HP\AppData\Local\Programs\Python\Python311\python.exe`.
- `.env`, `logs/app.log`, `drivelegal.db`, and `app/drivelegal.db` are tracked in this checkout even though `.gitignore` says environment variables/logs and generated artifacts should not be committed. Rotate any real secrets before public distribution.
- `JWT_SECRET` has an unsafe fallback string if unset. Production should fail fast instead of signing tokens with a fallback.
- OTPs and GPS fixes are stored only in process memory. They are lost on restart and are not shared across multiple workers/processes.
- CORS is configured with `allow_origins=["*"]`, `allow_methods=["*"]`, and `allow_headers=["*"]`.
- Dashboard/profile endpoints use `user_id` path parameters and do not currently enforce that the caller's JWT belongs to that `user_id`.
- `frontend/ui.html` hardcodes the backend URL and GPS interval; `.env`/`.env.example` values do not control them.
- The UI inserts chat message text into `innerHTML` after only replacing newlines, so server-returned text is rendered as HTML.
- `frontend/app.py` imports `json`, `requests`, and `streamlit` twice; `requests` is not used in the current wrapper.
- `requirements.txt` includes `slowapi`, but no current source imports or configures it.
- `HOST`, `PORT`, `BACKEND_URL`, and `LOG_LEVEL` are documented in `.env.example` but not currently consumed by code.
- `data/fines.json` notes `_last_updated` as `2024-01`; fine amounts should be verified against official authorities before production use. Jurisdiction hierarchy in fines.json should be validated against actual state/city-level traffic authority regulations.
- The international/regional scope layer is implemented in `rag/jurisdiction.py`, but the checked-in corpus and `data/fines.json` are still mostly India-focused. Add matching `region` payloads and fine keys before treating EU/ASEAN/GCC or Vienna Convention fallbacks as complete.
- `rag/chain.py` still prompts the LLM as an assistant for India, so international retrieval support should be paired with a more general prompt before broader-country use.
- USD equivalents in challan responses use static exchange rates in `rag/challan.py`; they are convenience hints, not live currency conversion.
- `scripts/preprocess.py` strips non-ASCII text, which may remove Indian-language text from raw law PDFs.
- Region filtering in `rag/retriever.py` uses exact matches. National chunks generated by preprocessing often use region `National`, while chat passes country `India`; the final unfiltered fallback still finds national content, but the country filter stage may not match those chunks.
- No Dockerfile, Compose file, or CI/CD config exists.
